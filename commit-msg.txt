One screen: no project step, every option visible, fullscreen

Three things asked for, and one defect found while doing them.

**No project creation.** The window keeps one session, names it after the day, and
opens it on launch. The project dialog, the open/delete list and the "name your
project" step are gone. What is *not* gone is the store: a batch of nine marked
segments that a restart forgets is a worse defect than the dialog it replaced, and
the audit trail, the export and the watch folder all read the same project. The
ceremony went, not the record.

**Every setting on the main window.** The delivery preset, the handles and the
verification policy were behind three collapsed sections; they are now three
columns on one row with their values visible. There is no `details` element left
anywhere, and `layout.spec.ts` asserts that — along with every named control being
visible at both 1920x1080 and the window's own 1000x620 minimum.

**Fullscreen.** `fullscreen: true` with a 1000x620 minimum, so an un-maximised
window on a laptop is still a layout rather than an overflow.

**The fields no longer stretch.** A `1fr` pair in a 1280 px column gave each
timecode a 620 px box around a 90 px number. They are capped at 320 px, the pair
sits together so the in point and the out point can be compared without moving your
head, and the length line no longer stretches so the button is under the settings it
acts on rather than pushed to the far right.

**A real defect the tests caught.** The Trim button was gated on `draft.ready`, so a
queue of nine segments could not be trimmed until a tenth range had been typed into
the fields. It now asks whether there is anything to *run* rather than whether there
is anything to *add*, and pressing it with a queue leaves the marks alone instead of
sweeping them into the run.

Deleted: ProjectsDialog, the `preview` model member that nothing called, and
SourceDialog replaces the project dialog (a dialog, not a screen, because "which
file" is a question with an end).

The head patch is untouched and re-verified: `crates/` has not changed since the
V1-parity commit, the differential oracle still agrees with the Python engine on 631
cases including 11 cut plans, and a real cut of 00:00:01:12 to 00:00:05:12 still
runs head-encode 37..50, copy 50.., join — with the body byte-identical to the source
by framemd5 and all 9 forensic checks passing.

12 browser tests, 9 unit tests, smoke-window passing, 404 Rust tests.
